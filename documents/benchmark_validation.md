# FloodTwin-HIL Benchmark Validation

### 1. Stage Objective

The Benchmark stage is the final scientific evaluation layer of the FloodTwin-HIL framework. Its purpose is to evaluate the complete system using a reproducible benchmark campaign and to quantify:

* Comparative estimation performance
* Component contribution through ablation
* Statistical strength of the observed improvements
* Overall validation-evidence quality

---

### 2. Evaluation Protocol

The final benchmark enforces a strict experimental protocol using the following parameters:

| Parameter                          | Configuration     |
| :--------------------------------- | :---------------- |
| **Input Scenarios**          | 30,000            |
| **Benchmark Evaluations**    | 30,000            |
| **Ablation Source Rows**     | 5,000             |
| **Ablation Experiment Rows** | 35,000            |
| **Depth Domain**             | $0 \dots 30$ cm |
| **Random Seed**              | 42                |

The benchmark preserves the strict separation between evaluation references and inference inputs. Ground-truth depth is used for post-hoc error and validation calculations only.

*Note: The 35,000 ablation rows represent 5,000 source scenarios evaluated across 7 ablation configurations, and therefore must not be interpreted as 35,000 independent source scenarios.*

---

### 3. Primary Benchmark Comparison

The benchmark evaluates the proposed framework against three principal references:

1. **Single-Sensor Reference**
2. **Fixed Fusion Baseline**
3. **Adaptive Fusion (Proposed)**

The primary evaluation metrics are:

* Root Mean Square Error (RMSE)
* Mean Absolute Error (MAE)
* Per-Sample Error
* Adaptive Win Rate
* Uncertainty Diagnostics
* Hazard-Related Outputs

The benchmark additionally records the best available single sensor on each sample as an **Oracle Diagnostic Reference**. This reference uses ground truth merely for theoretical evaluation bounding and does not represent a deployable inference strategy.

---

### 4. Primary Benchmark Results

Final results evaluated over 30,000 scenarios:

| Metric              | Single Sensor | Fixed Fusion |  Adaptive Fusion |
| :------------------ | ------------: | -----------: | ---------------: |
| **RMSE (cm)** |        0.5734 |       0.3071 | **0.2092** |
| **MAE (cm)**  |        0.4120 |       0.1903 | **0.1349** |

**Relative Improvement:**

* Adaptive vs. Fixed: $29.07\%$
* Adaptive vs. Single: $67.25\%$

**Adaptive Per-Sample Win Rate:**

* Adaptive vs. Fixed: $33.36\%$
* Adaptive vs. Single: $83.99\%$

*Note: The lower adaptive win rate against fixed fusion does not contradict the lower aggregate RMSE. RMSE reflects the magnitude of large errors, whereas the win rate measures the simple frequency of individual sample wins.*

### 6. Ablation Study

The benchmark executes seven controlled configurations to evaluate component contributions:

| ID          | Configuration            | Description                                                                    |
| :---------- | :----------------------- | :----------------------------------------------------------------------------- |
| **A** | **All Sensors**    | Proposed full adaptive configuration                                           |
| **B** | **No LiDAR**       | Excludes optical sensing modality                                              |
| **C** | **No Radar**       | Excludes RF sensing modality                                                   |
| **D** | **No Ultrasonic**  | Excludes acoustic sensing modality                                             |
| **E** | **No Reliability** | Removes reliability/health weighting while retaining valid sensor observations |
| **F** | **No Context**     | Excludes observable environmental context modulation                           |
| **G** | **No Adaptive**    | Removes all dynamic adaptive components (defaults to baseline)                 |

The ablation study determines whether the observed performance depends on individual sensors and on the principal adaptive/contextual components.

The `No Reliability` configuration is explicitly designed to isolate reliability weighting from sensor availability. Sensor availability is handled independently so that reliability is not inadvertently reused as a proxy for availability decisions.

---

### 7. Statistical Evaluation

Two primary paired comparisons are evaluated:

1. Adaptive vs. Fixed
2. Adaptive vs. Single

The predefined comparison family uses the **Holm Multiple-Comparison Correction**. The statistical evaluator outputs comprehensive metrics, including:

* Paired mean error difference
* Paired Cohen's $d$
* Hedges' $g$
* Paired $t$-test
* Wilcoxon signed-rank test
* Bootstrap confidence intervals
* Improvement confidence intervals
* Normality diagnostics
* Post-hoc statistical power
* Holm-adjusted significance

**Final Statistical Evidence:**

| Comparison                    | Mean Improvement | Hedges'$g$ | Result      |
| :---------------------------- | ---------------: | -----------: | :---------- |
| **Adaptive vs. Fixed**  |           29.07% |       0.3350 | Significant |
| **Adaptive vs. Single** |           67.25% |       0.7660 | Significant |

*Note: Extremely small $p$-values may numerically underflow to 0 in software outputs. For professional formatting, they should be reported using standard mathematical inequalities (e.g., $p < 0.001$) rather than $p = 0$.*

### 8. Validation Evidence Score

The `ValidationEvidenceScorer` summarizes the breadth and quality of the completed evaluation evidence. The score combines nine distinct scientific dimensions:

1. Dataset Coverage
2. Environment Coverage
3. Fault Coverage
4. Benchmark Breadth
5. Predictive Accuracy
6. Uncertainty Calibration
7. Statistical Evidence
8. Validation Stability
9. Hazard Validation

**Component Scores:**

The final score is an **Engineering-Defined Evidence-Quality Index**. It must not be interpreted as a statistical confidence level, a strict probability of correctness, or a certification of commercial deployment readiness. The clean benchmark evidence and dedicated statistical/fault evidence are supplied to the scorer as separate, isolated evidence sources.

---

### 9. Final Scientific Interpretation

The benchmark results support the following scientific conclusion:

> Under the evaluated 30,000-scenario computational benchmark, adaptive fusion achieves a lower aggregate depth-estimation error than the fixed-fusion baseline and the selected single-sensor reference, with statistically supported paired improvements and a "Strong" overall validation-evidence score.

Crucially, the benchmark does *not* establish any of the following claims:

* Universal superiority over every possible single-sensor system in existence.
* Absolute immunity to system failures.
* Guaranteed field-level generalization outside the Digital Twin bounds.
* Physical hardware-in-the-loop validation of actual physical sensors.
* Guaranteed deployment readiness for production autonomous vehicles.

Any claims extending into those domains require empirical evidence beyond the scope of this computational benchmark. As with any scientific evaluation, the conclusions are only valid under the stated assumptions and within the defined experimental scope.
